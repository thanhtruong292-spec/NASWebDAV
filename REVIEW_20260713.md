## CPU Usage Root Cause Analysis

**Top 3 hotspots (từ cao xuống thấp):**

1. **getSharedPreferences per recomposition** (120Hz = 120 file I/O/sec)
   - 3 vị trí: MainMenuScreen.kt:247, MainMenuScreen.kt:3214, SystemStatusCards.kt:97
   - **Fix:** wrap trong `remember(mContext)`
   - **Impact:** giảm I/O từ 120 → 1 lần mỗi recomposition của root

2. **realtimeNow 1s tick cascade recomposition**
   - MainMenuScreen.kt:248-254 — LaunchedEffect set `realtimeNow = System.currentTimeMillis()` mỗi giây
   - Truyền xuống 4+ children (MainMenuDashboardHeader, MainMenuDashboardSystemOverviewCard, ...)
   - Mỗi child recompose mỗi giây → full subtree recomposition
   - **Fix:** PanelFreshnessTag có ticker riêng (2s) → chỉ recompose bản thân tag (~30px label), không ảnh hưởng root hoặc siblings

3. **networkPingMs while(true) + 1s delay khi chưa login**
   - WebDavViewModel.kt:2773 — `while (true)` + `delay(1000)` khi `currentBaseUrl.isEmpty()`
   - **Fix:** `while (isActive)` để respect ViewModel scope cancel; `delay(10_000)` khi chưa login (-90% CPU khi offline)

**Kết quả kỳ vọng (estimate, cần verify trên thiết bị thật):**
- 120Hz I/O: từ 120 ops/sec → 1 op/sec (~99% reduction)
- Full-screen recompose: từ 1 lần/giây → 0 lần/giây (chỉ PanelFreshnessTag nhỏ recompose 1 lần/2s)
- Idle CPU: giảm đáng kể khi chưa login
